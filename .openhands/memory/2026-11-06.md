## Native verification method (added after PR-2)
- **NDK 28's libc++ does NOT implement `std::atomic_ref`.** Use `__atomic_load_n` /
  `__atomic_store_n` builtins instead (work on both clang and gcc). Host g++ DOES have
  atomic_ref, so host tests pass while the real APK build fails — always build the NDK target.
- Native build command (works, ~3 min, needs network for FetchContent):
  `cmake -S . -B /workspace/work/preloader-build -DCMAKE_TOOLCHAIN_FILE=$NDK/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-28 -DCMAKE_ANDROID_ARCH_ABI=arm64-v8a`
  then `cmake --build <dir> -j4`. `$NDK=/workspace/android-sdk/ndk/28.2.13676358`,
  cmake at `/workspace/android-sdk/cmake/3.22.1/bin/cmake`.
- Symbol audit: `llvm-nm -D --defined-only libpreloader.so | awk '{print $NF}'` (address is
  column 1 — do NOT grep for `^Java_` on the raw output).
- **Do NOT add a `--version-script` to the preloader**: 99 C++ `PL_EXPORT` declarations and
  native mods resolve `pl::` symbols from the host at dlopen. `--exclude-libs,ALL` is safe and
  removes the fmt/std leak (2624 -> 314 exports, JNI 145 + pl_ 9 + pl:: 126 all preserved).
