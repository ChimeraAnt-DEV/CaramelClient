## Merge of PR #181 (the pin bump + ambiguity fix)
- Merging `origin/main` into the branch conflicted **only** on the submodule gitlink plus the two
  memory files. main had moved to pin `0e562a6` (the same branch tip) while the branch pinned
  `9ee3650` (merged main). `git diff 0e562a6 9ee3650` touches only the three ambiguity-fix files,
  so taking the branch's pin is lossless — verified, then staged the gitlink directly.
- **A submodule conflict has three stages**: `git ls-files -u <path>` shows stage 1 = the merge
  base pin (`463c63a`), 2 = theirs/main (`0e562a6`), 3 = ours (`9ee3650`). `git checkout
  --theirs` on a gitlink does not work the way it does for a file; setting the submodule working
  tree to the wanted commit and `git add <path>` is what actually stages the gitlink.
- Merged as `05efa49`; `Android CI` + `Build Debug APK` both green on main afterwards.
- **The `merge-async` endpoint is the right call but it enqueues**: the first attempt failed with
  "Pull Request has merge conflicts" (a stale `sha` guard doing its job, not an API error), and
  after the merge commit + push it returned `status: merged`.

- **A run with `conclusion: failure`, `total_count: 0` jobs and no annotation means GitHub
  rejected the workflow file**, not that a step failed. The message is not in the API at all; run
  **`actionlint`** on the file. Downloaded `actionlint` 1.7.7 + `shellcheck` 0.10.0 to /tmp and
  /usr/local/bin. The bug: `runner.temp` is **not allowed in a job-level `env:`** (only
  `github`, `inputs`, `matrix`, `needs`, `secrets`, `strategy`, `vars`); move it to the step.
- **SIGPIPE is the trap in every `set -o pipefail` symbol check.** `nm -D ... | grep -q " sym$"`
  exits 74 (128+SIGPIPE) even when the symbol IS present, because `grep -q` exits on the first
  match and closes the pipe. My first CI run failed 3 jobs on this class of bug. Fix: write the
  table to a file once, then `grep -q pat file`. Same shape in `ls -d glob | head -1`
  (`run_tests.sh` NDK sysroot lookup) -> `find ... -print -quit`. Note it does NOT reproduce with
  one NDK / small output, so it is latent until a second one is installed.
- **`cargo fmt --check` failed on a tree that had never been rustfmt'd** (157 sites, 30 files).
  No `rustfmt.toml` rescues it (max_width 100/120 + use_small_heuristics variants all leave

  normalizing first.
- **`run_tests.sh` cached its fetched headers four levels above its root** — correct as the
