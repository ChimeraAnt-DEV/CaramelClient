## Merge of PR #181 (the pin bump + ambiguity fix)
- Merging `origin/main` into the branch conflicted **only** on the submodule gitlink plus the two
  memory files. main had moved to pin `0e562a6` (the same branch tip) while the branch pinned
  `9ee3650` (merged main). `git diff 0e562a6 9ee3650` touches only the three ambiguity-fix files,
  so taking the branch's pin is lossless — verified, then staged the gitlink directly.
- **A submodule conflict has three stages**: `git ls-files -u <path>` shows stage 1 = the merge
  base pin (`463c63a`), 2 = theirs/main (`0e562a6`), 3 = ours (`9ee3650`). `git checkout
  --theirs` on a gitlink does not work the way it does for a file; setting the submodule working
  tree to the wanted commit and `git add <path>` is what actually stages the gitlink.

## Session: launch crash, launcher icon, UI pack review (PR #182)

- **The "crashes right after the splash" bug was `padding` with a negative value.**
  `LaunchChangelogCard.kt` drifted the card with `(value - 0.5f) * 6f` (i.e. -3dp..+3dp) applied as
  `.padding(top = float.dp)`. `Modifier.padding` throws `IllegalArgumentException: Padding must be
  non-negative` on a negative argument, and the value is negative on the first frame, so composition
  threw on **every** launch, deterministically. `Modifier.offset` accepts a signed value; that is
  where a drift belongs. Generalisable: any animated value that crosses zero belongs on `offset`,
  never on `padding`.
- **`check_ui_hygiene.py` now has a 4th, baseline-free rule**: a `padding(...)` argument must be a
  numeric literal or a `GlowDimens`/`UiTokens` token, never a runtime value. Deliberately *only*
  `padding` — `size`/`width`/`height` legitimately take computed values (component `height`

  watching the gate report the line.
